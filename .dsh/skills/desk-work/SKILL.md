# 坐班做事

把自己当成坐在桌前的人：先听清要干什么，再动手，做完给交代。不是聊天，是把活干完。

## 接活

1. 一句话复述目标，确认对象、时限、交付物；
2. 缺关键信息（给谁、用什么文号、放哪个目录）就问，不要猜；
3. 判断这件事属于哪条通道：

| 活 | 通道 |
|---|---|
| 收文、查清单、发通知 | `shouwen` / `gongwen` 的脚本，走 HTTP，不开界面 |
| 网页表单、后台操作 | `browser`（CDP 元素级） |
| 桌面程序、游戏、必须看界面 | `virtual-screen` 准备画布 + `gui-operator` 截图操作 |
| 读文件、整理目录 | `fs` 工具，移动/删除按安全规则 |
| 要留痕的工作 | `specialty/work/work.py` 记步骤 |

## 干活的节奏

```powershell
python specialty/work/work.py start --title "处理今日收文"
python specialty/work/work.py step --note "查收今日文件" --artifact <产出路径>
python specialty/work/work.py finish --summary "收 6 件，转发 1 份"
python specialty/work/work.py report
```

- 开工、收工各一条气泡（有桌宠时）；长任务在关键节点再报一次，别刷屏；
- 每一步都要有可复核的结果：文件路径、截图、命令输出，不要只说“已完成”；
- 失败就停在那一步，记录错误原文，不要跳过继续。

## 交活

最后给一份简短交代，按这个顺序：

1. 做完了什么（一句）；
2. 产出在哪（文件/目录，带路径）；
3. 没做完的、卡住的、需要用户确认的（列清楚）；
4. 下一步建议（可选）。

不编数字、日期、文号；用户没给的写「待核实」。

## 规矩

1. 不可逆动作（删除、提交、发布、付款、发消息）先问，再执行；
2. 一次只推进一件主任务，旁支记下来另开；
3. 界面操作按 `gui-operator` 的规矩：截图、按文字点、动作后复核；
4. 收工前把 `report` 贴给用户，或把报告文件路径给出来；
5. 不把用户文件和密钥拷进仓库。
