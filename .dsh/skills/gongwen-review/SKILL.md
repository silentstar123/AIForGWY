# 公文审稿

先跑检查，再读内容。不要只给“基本规范”这种空话。

## 步骤

1. 判断文种。稿子自己写错文种时，在意见里指出应该用的文种和理由。
2. 运行 `node specialty/gongwen/check.mjs review <文种> --file <草稿>`。结构缺项、附件有没有名称、请示是不是多处请求批准，以及文号、日期、金额会在一份结果里。
3. 用户给了原稿和改稿时，再跑 `node specialty/gongwen/check.mjs diff --left 原稿.md --right 改稿.md`。只对上两边的文号、日期和金额，不替用户决定哪一份对。
4. 按下面的单子逐项看，每条意见写：位置、问题、改法。

## 必查

- 一文一事。请示里夹了第二件要批准的事，拆开。
- 转发通知正文是否被拆成「一、二、三」；应写成一段话（缘由 + 现转发给你们，请……），拆条的要标出并合并。
- 主送和正文对得上。请示不能主送给平级，函不能写成命令下级的口气。
- 结语和文种一致。报告里出现「请批示」要标出。请示没有「请批示」或「请批复」要标出。
- 时间、金额、人名、文号前后是否一致。对不上的并列出来，不要选一个当成对的。
- 依据段里的文件名称和文号，稿子没写来源的，标「待核实」，不要补全。
- 有没有把内部过程、个人情绪、尚未决定的事项写成已经决定。

## 意见怎么交

先写三行：文种是否用对、能否送审、必须改的条数。然后按「必须改 / 建议改 / 待用户确认」分组。必须改只放会让公文用错对象、用错文种或写进未核实事实的问题。
