# 汇报与会议整理

结论放在最前面。领导要先看到决定、风险和需要拍板的事。

## 边界

- 出席人、发言、数据只来自用户给的记录。记录里没有的发言不要补。
- 没定的事写成「待决」，不要写成已经议定。
- 纪要定稿前用公文起草技能里的纪要体例，并跑 `node specialty/gongwen/check.mjs lint 纪要 --file <稿>`。

## 一页纸汇报

按这个顺序写，每段不超过五句：

1. 结论：现在什么状态，一句话。
2. 要领导定的事：每条一个选项，写明不选会怎样。
3. 进展：已经完成的，带日期。
4. 风险：什么事、影响谁、建议谁在何时前处理。
5. 下一步：负责人和日期。没有日期就标「待排期」。

## 从记录到纪要

1. 先列会议名称、时间、地点、主持人、出席、缺席、列席。记录没写的格子留空。
2. 把发言收成议题，不按发言人流水账抄。
3. 只有明确说出「同意」「确定」「由谁负责」的，放进议定事项。
4. 每条议定事项写成：事项、负责人、完成时限、完成标志。
5. 分歧保留成「有两种意见」，不要折中编一个新结论。

讲话提纲用 `office-draft`：`node specialty/gongwen/check.mjs scaffold 讲话 --title "标题"`。不替领导编表态。
