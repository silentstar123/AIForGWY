# 事务文书

这些不是通知、请示那类法定文种。不要套「妥否，请批示」，也不要编文号。

## 步骤

1. 确认是方案、简报、拟办、讲话、总结、督办、办文中的哪一种。
2. 取骨架：`node specialty/gongwen/check.mjs scaffold <文种> --title "标题"`
3. 只用用户材料填空。没有的数字、日期、人名写成「待核实」。
4. 一次看结构项和事实：`node specialty/gongwen/check.mjs review <文种> --file <草稿.md>`。文号、日期、金额每一条都要能指回用户材料。

## 写法

- 方案：目标写成可以核对的结果。范围写清做什么、不做什么。每一步有负责人和时限。风险写影响和谁处理。
- 简报：导语一句说完何时何地何事结果。文中每个数都进「数据来源」。不写请示。
- 拟办：先写来文标题。文号用户没给就写「无」。意见用「建议某处于某时限前做什么」，不写成已经批准。
- 讲话：写场合和听众。开头先说要解决什么。分点写。结尾的要求落到人。不替领导编表态，不编现场数据。
- 总结：完成情况只写已经发生的事。没做完的放进问题，不要写成完成。下一步写负责人和时限。
- 督办：写事项、来源、承办单位、时限和怎样算办完。来源不是用户给的纪要或批示，就写「待核实」。不把未反馈写成已办结。
- 办文：用来登记一件收文。写来文机关、标题、文号、拟办意见、承办处室和反馈时限。没有回执之前，办理结果保持未办结。

法定公文仍用 `gongwen-draft`。
